**Decision status — PROPOSED.** The four `/1` profiles below have CE consumers. The shared OpenAPI describes those consumers and a fixture service. Production activation requires a separately reviewed real provider. The *StudyGraph AI — Capstone 2 Execution Plan* (pp. 5–11, 14) governs ownership and requirements. ## Implementing the four profiles

Use the base URL of the service, then append the full path from the OpenAPI. Its release version is `1.0.0-rc.1`. Each profile independently negotiates its wire version through `X-StudyGraph-Protocol: studygraph.<profile>/1`. All eight operations require that header and `Authorization: Bearer <AI_SERVICE_TOKEN>`, an internal credential of at least 32 characters. CE-3 provisions service credentials and transport security for deployment. The private boundary carries no end-user credential.

| Profile / provider | Authenticated GET | Authenticated POST | Successful business result |
| --- | --- | --- | --- |
| Index / AI-1 | `/ai/v1/index/capabilities` | `/ai/v1/index/documents` | Committed generation receipt, including content identity and counts |
| Chat / AI-1 | `/ai/v1/chat/capabilities` | `/ai/v1/chat/answer` | One complete answer with verifiable evidence, or insufficient evidence |
| Quiz / AI-1 | `/ai/v1/quiz/capabilities` | `/ai/v1/quiz/generate` | Requested number of grounded questions with private answer keys |
| Mastery / AI-2 | `/ai/v1/mastery/capabilities` | `/ai/v1/mastery/update` | Complete event accounting and one score per affected topic |

Start with the GET. Return a literal boolean `mock: false` only for a real implementation. CE caches probe outcomes, checks the protocol and capability values, and intersects them with local policy before sending work. Scope advertisement never grants access. Index checks synchronous completion, locator support and byte limit. Chat checks scope and question length. Quiz checks scope, supported types and count/topic limits. Mastery also checks pinned model name, version, state epoch, ordering and batch size.

POST bodies and all replies are UTF-8 `application/json`. Use exact field names and types, including nullable fields that are required. Return one Content-Length equal to the encoded byte count and use identity encoding. Reject duplicate object members and nonfinite numbers. Emit integers without a fractional part or exponent. Use lower-case canonical UUIDs. CE refuses redirects, ambiguous framing and unexpected result keys. The schema documents field-level rules. Request-dependent echoes, evidence, sequencing, permissions and database facts also require application checks.

Errors use `{"error":{"code":"invalid_request","message":"Invalid input.","retryable":false}}`. Send 401 for incorrect credentials, 400 for an incompatible protocol header or inconsistent content identity, 422 for invalid typed content, and 503 for temporary unavailability. Keep diagnostics free of credentials, learner IDs and educational content. HTTP status, operation and delivery state determine CE retry behavior. Index can retry the same content key after a lost response. Chat and quiz issue one business POST per accepted operation. Mastery retries through its fenced outbox. The published responses and examples are in the [OpenAPI](../contracts/ai-service.openapi.yaml) and [fixtures](../contracts/fixtures/).

### Index

Form a JSON object containing exactly the `protocol`, `document` and `sections` members and hash its canonical bytes. Use UTF-8, recursively sorted keys, compact separators, preserved Unicode and array order. Encode SHA-256 as lower-case hex. Hash the UTF-8 concatenation of protocol, document UUID, course UUID and that hex digest, separated by three single NUL bytes, to obtain the idempotency key. Include digest and key in the transmitted canonical JSON and send the identical key in `Idempotency-Key`. Include null document fields. Job ID, attempt number and timestamps never participate.

Section ordinals start at zero with no gaps. Physical PDF pages strictly increase, are positive and lie within the known page count. Harvested versions instead carry immutable attribution, a null page count and section locators. Only the first section may be the unnamed level-zero lead. Named headings have levels 2–6. Send the latter form only after negotiating `section`. Omitted `locators` means page-only.

AI-1 must atomically commit one generation with its chunks and embeddings before issuing a real 200. Echo document, course, digest, key and section count, with a positive committed chunk count. A duplicate produces the same identity and counts with `replayed: true`. Serialize concurrent duplicates or return retryable 409 `in_progress`. A different key for an already committed document returns permanent 409 `generation_conflict`, a different course returns permanent 409 `course_mismatch`. A 202 or lost reply leaves completion unconfirmed.

**F03 deployment gate.** Revision 0009 provides an atomic PostgreSQL writer and course-scoped reader. CE rehashes the locked source and checks its committed generation, actual vectors, source evidence, receipt counts and live claim before publication. Keep `INDEXING_ENABLED=false` pending joint approval, CE-3 provisioning and AI-1 staging verification. [Database operations and rollout](ai-indexing-integration.md#8-durable-postgresql-handoff-revision-0009)

### Chat and quiz

Chat echoes request UUID, course and authorized scope. Honor the received origin list, citation count and answer character budget. `class_only` permits class chunks. `class_plus_external` adds visible external material accepted for the same course when enabled. Live web is unavailable. Use `used_web: false`. A grounded answer uses canonical inline markers such as `[1]`; every referenced marker maps to exactly one citation and every citation is used. Include exact chunk and document UUIDs, origin and source quote. CE matches the normalized quote against its own passage (at least 20 characters or the whole shorter passage), verifies access and derives public title, locator, link and snippet. For insufficient evidence return `grounded: false` with empty citations. The public SSE stream is CE-owned and delivers verified content. [Chat protocol and public delivery](ai-chat-integration.md)

Quiz accepts class sources only. Return exactly the requested count of distinct stems for requested topics, negotiated types and requested difficulty (`mixed` allows any supported difficulty). MCQ has 2–6 distinct choices and an in-range zero-based integer answer. True/false has null choices and a literal boolean answer. Give 1–4 distinct citations per question with exact document, chunk, locator and quote. Supply model name/version. Enforce the transmitted length limits and keep the correct answer out of stems and hints. CE verifies evidence and membership, fences the session, shuffles choices, stores private keys and grades answers. The public idempotency key and CE session replay are separate from the upstream request UUID. AI-1 has no write access to sessions, attempts or answer keys. [Quiz protocol and evidence rules](ai-quiz-integration.md)

### Mastery

Treat course and learner references as opaque HMAC-SHA256 values. CE derives them from the deployment namespace, secret key and identities. Only the frozen batch UUID, epoch, references, namespace and minimal graded events cross this boundary. Order each topic by increasing sequence and apply each event once within its epoch and learner stream. Retries keep the same batch. `hint_used` and `response_ms` are untrusted telemetry. Preserve model state across restarts, and change the epoch through a coordinated recovery if state is lost.

Echo request UUID, epoch, course and learner refs. Echo the pinned model. Applied and duplicate IDs must be disjoint and unique and together cover exactly the submitted events. Return one finite score in [0,1] per batch topic, including duplicates. Both `through_seq` and `attempts_seen` equal the last submitted sequence for that topic. Return an offset-bearing RFC 3339 review timestamp or null. CE applies bounds against database time and persists only after checking its lease, attempt token and model state. Lost state or identity changes can block delivery. AI-2 owns model computation and internal deduplication. CE owns events, projections, review visibility and reconciliation. [Mastery protocol and recovery](ai-mastery-integration.md)

## Proposed usage metadata

The plan requires usage on every response. Existing `/1` bodies reject additional keys. The following optional HTTP extension requires joint CE/AI approval and accounting support. No current CE client requests it. A provider may omit the complete extension. CE must interpret absence as unavailable.

A future client requests `X-StudyGraph-Usage-Profile: studygraph.usage/1`. An implementing provider opts in by echoing that header and returning the following single-valued response headers. Ignore unnegotiated or unknown versions. The proposal covers successful and failed executions. Capability probes and failures before execution may omit the group.

| Header | Proposed value and meaning |
| --- | --- |
| `X-StudyGraph-Execution-Id` | Stable opaque provider execution ID, unique within the provider deployment. Required when reporting an execution. Never include user, course or prompt data. |
| `X-StudyGraph-Model`, `X-StudyGraph-Model-Version`, `X-StudyGraph-Prompt-Version` | Provider identifiers, or literal `unknown` when unavailable. Model identity must agree with any pinned body identity. |
| `X-StudyGraph-Latency-Ms` | Original provider execution duration in whole milliseconds, or `unknown`. CE measures transport time separately. |
| `X-StudyGraph-Input-Tokens`, `X-StudyGraph-Output-Tokens` | Metered counts or `unknown`. Zero is a measured zero. No estimated costs or inferred counts. |

Use visible ASCII tokens matching `[A-Za-z0-9][A-Za-z0-9._-]{0,99}` for execution IDs. Model and prompt identifiers may additionally contain `:`, `/` and `+`, matching the mastery model alphabet. Reserve `unknown` for unavailable metadata. Numeric values are unsigned base-10 integers bounded by signed 64-bit range. Duplicate or malformed headers invalidate usage accounting, without changing a valid business outcome. A replay of a stored result reports the original execution ID and original measurements, counted once per deployment/execution. A new inference on a retry has its own execution ID. If the original usage cannot be retrieved, omit the group or use `unknown` for missing measurements. Pricing, retention, multi-model attribution and reconciliation need CE-1, AI-1 and AI-2 agreement before enabling cost reports.

## Run conformance

From the repository root in a clean Python 3.11 environment:

```sh
python -m pip install -r services/core-api/requirements-dev.txt -r contracts/requirements-test.txt
PYTHONPATH=services/core-api python -m pytest -q contracts/tests
docker build -t studygraph-ai-contract -f services/ai-service/Dockerfile .
docker run --rm --network none -i studygraph-ai-contract python - < contracts/tests/check_mock_image.py
```

Each shared JSON file contains a real-provider-shaped `capabilities`, a CE `request`, an expected `response`, and `invalid_responses`. Apply each negative case's `path` and `value` to a fresh response copy. `schema_valid: true` marks a structurally valid counterexample that fails semantic validation. The index file includes a second complete example for external sections. All identifiers, passages and measurements in fixtures are synthetic. AI providers can import these files directly as test vectors and replace the canned computation in their own isolated test environment. For chat/quiz, seed the synthetic document/chunk in the provider's isolated corpus to exercise evidence matching. Real generation should satisfy evidence and semantic checks across other inputs too.

The packaged mock accepts the published examples and fresh request UUIDs for chat, quiz and mastery. It rejects other inputs and always identifies itself. Its single-process index replay and mastery deduplication reset at restart. Set a development-only `AI_SERVICE_TOKEN` to exercise it. Health is public; the mock refuses business requests when the secret is absent. Positive CE integration tests use isolated injected providers. Use the disposable PostgreSQL/Redis runner for consumer lifecycle behavior, for example `bash services/core-api/scripts/test_migrations.sh -q tests/test_index_worker_integration.py tests/test_chat_api.py tests/test_quiz_api.py tests/test_mastery_delivery.py`.

Release gates also include AI-1 retrieval isolation and quality on real material, AI-2 model/epoch recovery and evaluation, CE-3 service credentials and user authorization, measured deadlines against plan budgets and joint acceptance of deferred requirements. Contract validation and fixture execution exercise the wire boundary. Real model quality, restricted PostgreSQL persistence and end-to-end publication each need their own verification.
